# Plan X

Веб-интерфейс для задач и заметок. Браузер открывает обычные Markdown-файлы из одной разрешённой папки Google Диска. На Mac ту же папку можно открыть как хранилище Obsidian через Google Drive for desktop. Другой редактор может обновлять файлы на Диске по своему доступу.

## Открыть

Интерфейс состоит из статических файлов для GitHub Pages. Чтобы посмотреть вымышленные примеры, откройте «Диск», нажмите «Открыть вымышленную базу» и выберите «Тестовая база». Для локальной проверки запустите `python3 -m http.server 8080 --bind 127.0.0.1` в корне проекта и откройте `http://127.0.0.1:8080/`.

На главной задачи определяются по папкам «Личное» или «Петроработа» и «Текущие» или «Долгосрочные». Для совместимости с прототипом поддерживаются свойства `group: personal|work` и `lane: current|later`. Источник дайджеста настраивается в разделе «Диск». Можно выбрать конкретный файл или папку, из которой отображается последняя заметка. Дневные планы доступны в проводнике.

## Изолированная папка Google Диска

Выбор папки с OAuth scope `drive.file` ограничивает доступ приложения выбранными объектами. Google отдельно описывает [per-file scope](https://developers.google.com/workspace/drive/api/guides/api-specific-auth). [Опубликованный эксперимент с Picker](https://stackoverflow.com/questions/79702574/selecting-a-folder-in-the-google-picker-with-the-drive-file-scope) показывает, что существующие дочерние файлы такого доступа автоматически не получили.

Plan X использует коннектор с отдельным сервисным аккаунтом Google. В Google Диске этому аккаунту предоставляется доступ к одному корню. Коннектор проверяет заданный корень и родительскую цепочку файла, обходит вложенные папки и пропускает ярлыки. Пользователь выбирает этот корень один раз в разделе «Диск». Новый вход потребуется после истечения 12-часового сеанса или закрытия вкладки. Выбранная папка останется в настройках браузера. Несохранённые правки хранятся в сессии вкладки.

### Пилот

1. Используйте отдельную папку с вымышленными `.md`, включая хотя бы одну вложенную папку. Владелец файлов остаётся прежним. Чтению достаточно роли читателя. Для записи потребуется роль редактора только на тестовой папке.
2. Запустите `connector/server.mjs` на Node.js 22+ за HTTPS. Для локального теста подходит loopback. Установите `PLANX_FOLDER_ID`, `PLANX_WEB_ORIGIN` и `PLANX_ACCESS_CODE` (32 случайных байта в hex, например `openssl rand -hex 32`). Origin должен соответствовать адресу интерфейса без пути. Код вводится в разделе «Диск». Не храните параметры развёртывания в репозитории.
3. Для среды Google Cloud задайте `PLANX_SIGNING_SERVICE_ACCOUNT`. Её runtime identity должна иметь возможность вызвать `iam.serviceAccounts.signJwt` только для выделенного аккаунта. Для разрешённого локального окружения поддерживается `PLANX_SERVICE_ACCOUNT_FILE` с путём к уже выделенному закрытому файлу учётных данных. При запуске укажите один способ. Браузер получает только короткий сеанс Plan X.
4. Проверьте чтение с Mac и iPhone. После разрешения записи для пилота создайте вымышленный файл `planx-cas-fixture.md` с первой строкой `# Plan X CAS fixture`. Передайте его ID в `PLANX_CAS_FIXTURE_ID`, задайте `PLANX_SYNTHETIC_CAS_TEST=yes` и запустите `node connector/probe-cas.mjs` с доступом сервисного аккаунта. Скрипт проверяет три вещи: обновление и чтение того же файла, отклонение устаревшего If-Match и ровно одну успешную запись при двух одновременных попытках. Он меняет только эту вымышленную заметку.
5. Включайте `PLANX_CAS_PILOT_VERIFIED=yes` только после успешной проверки на том же типе Диска и типе Markdown-файла. Запись использует [один условный multipart PUT в Drive API v2](https://developers.google.com/workspace/drive/api/reference/rest/v2/files/update) с ETag. Редактор доступен, если есть валидный ETag и прочитанный текст соответствует контрольной сумме в метаданных. Атомарность записи проверяется отдельно в пилоте.

После конфликта Plan X показывает текущую версию и оставляет черновик в редакторе. После обрыва во время записи пользователь может прочитать текущую версию и проверить, успели ли изменения сохраниться. Автоматической повторной записи нет.

## Проверки

```sh
npm install
npm test
npx playwright install webkit
npm run test:browser
```

Браузерные проверки используют профиль iPhone и десктопный WebKit. Тесты модели, коннектора и интерфейса используют вымышленные данные или имитацию Google API. Живой результат проверяется в пилоте отдельно.
